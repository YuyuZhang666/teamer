# Cocos 微信小游戏基础框架设计

## 状态

本设计依据用户已经确认的技术路线直接执行，无需中途方案确认。

## 目标

建立一个可由 Cocos Creator 3.8 LTS 打开、预览并构建为微信小游戏的竖屏工程。首个可见版本只证明“工程、场景、动画基础层和微信配置能够工作”，不加入剧情、角色、美术资产或正式玩法。

## 体验边界

- 设备方向：竖屏。
- 设计分辨率：750 × 1334，适配异形屏安全区。
- 首屏：中性科技感背景、轻量循环动效、工程状态文字；不出现故事内容。
- 交互：保留一个无业务含义的触摸反馈，用来验证手机输入链路。
- 性能基线：30 FPS 作为低端机保底目标；此阶段不加载外部 3D 模型、实时阴影或后处理。
- 微信小游戏 AppID：`wx79a1c555206206f6`。

## 技术路线

- 引擎：Cocos Creator 3.8 LTS。
- 语言：TypeScript。
- 最终视觉方向：风格化低多边形 3D 场景 + 骨骼动画 + 世界坐标交互标记。
- 当前框架：一个 Boot 场景、独立的应用生命周期状态机、微信平台适配入口、UI 安全区布局与可复用动效组件。
- 自动化测试：Node.js 内置 test runner 测试不依赖引擎的 TypeScript 核心逻辑；Cocos 场景与微信产物通过构建烟雾检查验证。

## 工程边界

```text
assets/
  scenes/              Boot 场景
  scripts/
    app/               应用启动与生命周期
    core/              无引擎依赖的状态、事件与配置逻辑
    platform/          微信/浏览器能力边界
    presentation/      视图、适配、动效组件
  resources/           后续按需动态加载的资源入口（当前为空）
settings/              Cocos 项目设置（需纳入版本控制）
tests/                 Node 可执行的核心逻辑测试
scripts/               构建产物和微信配置校验脚本
build/wechatgame/      Cocos 生成的微信小游戏产物（不纳入版本控制）
```

## 启动流程

1. Boot 场景加载 `AppBootstrap`。
2. 核心状态从 `cold` 进入 `ready`。
3. 平台层判断微信环境或浏览器预览环境。
4. 视图层读取安全区并排布状态面板。
5. 背景动效开始循环；任意触摸只触发一次可见反馈，不推进剧情。

## 验收标准

- Cocos Creator 3.8 LTS 可以无丢失脚本/组件错误地打开工程。
- Boot 场景在竖屏预览中可运行，状态从“正在初始化”变为“框架运行正常”。
- 背景存在持续但克制的动画，点击/触摸存在反馈。
- 核心状态与平台判定测试全部通过。
- 能生成 `wechatgame` 构建目录，微信项目配置包含给定 AppID、`compileType: "game"` 和竖屏方向。
- 微信构建使用显式的轻量引擎模块白名单，生成目录总大小不超过 4 MiB；体积上限由自动化测试和产物校验共同守护。
- 微信开发者工具能够导入构建目录；若手机预览需要用户扫码登录，则将该动作明确记录为唯一人工边界。
- README 给出从 Creator 打开工程到微信真机预览的最短路径。

## 非目标

- 不实现开场剧情、角色命名、职场关卡、解谜、连连看或存档系统。
- 不采购或生成正式美术、音乐、模型与字体。
- 不上传代码、不发布体验版、不调用微信后台业务接口。

## 关键决策

- 使用 Cocos 而不是团结引擎：目标画面属于轻量风格化 3D，Cocos 足以实现，并能减少微信小游戏包体和导出链路成本。
- 首版采用“可见的空框架”而非纯黑空场景：手机端可直接判断渲染、动画、输入和安全区是否都已生效。
- `.scene`、`.meta` 和项目设置优先由官方 Creator 生成，避免手写私有序列化格式造成版本不兼容。
- 当前发布配置只打入启动空壳实际所需的 2D/UI/Graphics/Tween 渲染能力；未来加入 3D、骨骼动画、音频或物理时，必须显式扩展模块白名单并重新通过 4 MiB 门禁。
